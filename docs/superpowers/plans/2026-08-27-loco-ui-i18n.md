# Locomotion L3 + UI U3 + i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship local VRChat-style locomotion with Warudo-style additive layers, Warudo-like OneConfig sections, VRChat-like radial menu, and `en_us`/`ko_kr` key parity.

**Architecture:** Extract Minecraft entity motion into a compact `LocoParams` record; blend Idle/Breathing/Swaying/Overlay/Locomotion into humanoid bone rotations applied before or instead of `VrmRig.apply` PlayerModel retarget; extend OneConfig and add a radial HUD driven by translation keys.

**Tech Stack:** Fabric 26.2, Java 21, JOML, OneConfig, existing `VrmRuntime`/`VrmRig`

**Spec:** `docs/superpowers/specs/2026-08-27-multiplayer-vrm-loco-design.md`

## Global Constraints

- Minecraft / Fabric: 26.2 / fabric-api from `gradle.properties`
- No copyrighted VRChat proxy animation binaries in the repo
- No Gesture/FX hand layers in v1
- All new user-facing strings use translation keys with identical `en_us` and `ko_kr` key sets
- Prefer loco stack; fall back to existing `VrmRig.apply(PlayerModel)` when clips unavailable
